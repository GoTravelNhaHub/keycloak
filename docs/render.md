# Deploying Keycloak to Render

`render.yaml` is a Render Blueprint. It creates:

| Resource | Name | Plan | Region |
| --- | --- | --- | --- |
| Render Postgres 17 | `keycloak-db` (database `keycloak`, user `keycloak`, 5 GB disk) | `0.1c-256mb` (Basic) | singapore |
| Docker web service | `keycloak` (built from `Dockerfile`) | `1c-2g` | singapore |

The database has an empty `ipAllowList`, so only Render services in Singapore can reach it, over the internal network. Keycloak gets `DATABASE_URL` (Render's internal connection string), and `docker/entrypoint.sh` converts it into the JDBC URL Keycloak needs.

Do not use the free plans. Free Postgres is deleted after 30 days. A free or 512 MB web service either sleeps (a 30-second-plus cold start breaks logins) or runs out of memory. Check current prices at render.com/pricing.

## 1. Put `keycloak/` in a GitHub repo

Render deploys from a Git repo. This folder is its own repo, so `render.yaml` and the `Dockerfile` sit at the repo root:

```bash
cd keycloak
# create an EMPTY private repo first, e.g. github.com/dntuanvu/gotravelnha-keycloak
git remote add origin https://github.com/dntuanvu/gotravelnha-keycloak.git
git push -u origin main
```

`.env` is git-ignored. The realm file holds `${PLACEHOLDERS}` only, no secrets.

## 2. Create the Blueprint

1. Render dashboard → **New → Blueprint** → connect the repo → branch `main`.
2. Render prompts for the `sync: false` values:
   - `KC_HOSTNAME`: `https://auth.gotravelnha.com` (recommended; see step 3). Alternatively, use the `https://keycloak-xxxx.onrender.com` URL to try it out first.
   - `SMTP_PASSWORD`: your Resend API key. Leave it empty for now if you don't have one; verification and reset emails will fail until you set it.
3. **Apply**. Render creates the database first, then builds the image (about 2–4 minutes) and starts it. The first boot imports the `gotravelnha` realm, using `GTN_WEB_URL=https://www.gotravelnha.com` and `FH_WEB_URL=https://familyhub.app` for the redirect URIs.
4. The deploy is done when the service shows **Live**. Its health check is `GET /health/ready` on port 8080.

`GTN_WEB_CLIENT_SECRET`, `IAM_ADMIN_CLIENT_SECRET` and `KC_BOOTSTRAP_ADMIN_PASSWORD` are generated by Render. To see them: **keycloak → Environment**.

## 3. Custom domain `auth.gotravelnha.com`

1. **keycloak → Settings → Custom Domains → Add** `auth.gotravelnha.com`.
2. At your DNS provider, add `CNAME auth → keycloak-xxxx.onrender.com` (Render shows the exact target). If you use Cloudflare, set the record to **DNS only**, not proxied, until Render has issued the certificate.
3. Wait for Render to show the domain as verified and the certificate as issued.

`KC_HOSTNAME` must match the URL people use. Until DNS resolves, the admin console and logins redirect to a domain that doesn't work yet; the health check is unaffected. To change the hostname later, edit `KC_HOSTNAME` and redeploy. That changes the token issuer, so every app's issuer setting must change with it.

## 4. First login and hardening

1. Open `https://auth.gotravelnha.com/admin` and sign in as `admin`, using the generated `KC_BOOTSTRAP_ADMIN_PASSWORD`.
2. In the **master** realm, create your own admin user, give it the `admin` role, and sign in as that user. Then delete the bootstrap `admin` user. You can delete `KC_BOOTSTRAP_ADMIN_*` from the environment too; they're only used while master has no admin.
3. Check that **gotravelnha → Clients → gotravelnha-web → Valid redirect URIs** shows `https://www.gotravelnha.com/auth/keycloak`.
4. Optional: add Google sign-in under **gotravelnha → Identity providers → Google**, with Google redirect URI `https://auth.gotravelnha.com/realms/gotravelnha/broker/google/endpoint`.

## 5. Wire the apps (see `integration.md`)

| App | Env to set | Value |
| --- | --- | --- |
| web (Vercel) | `NUXT_OAUTH_KEYCLOAK_SERVER_URL` | `https://auth.gotravelnha.com` |
| | `NUXT_OAUTH_KEYCLOAK_CLIENT_SECRET` | Render's `GTN_WEB_CLIENT_SECRET` |
| familyhub API (Render) | `OIDC_ISSUER` | `https://auth.gotravelnha.com/realms/gotravelnha` |
| familyhub web (Vercel) | `VITE_OIDC_ISSUER` | same issuer |

## Operating it

- **Deploys:** `autoDeploy` is off, so pushes don't restart IAM by accident. Deploy with **Manual Deploy → Deploy latest commit**. Each deploy restarts the single instance, so expect about 20 seconds of login downtime.
- **Realm changes after the first boot:** `realm/gotravelnha-realm.json` and its env placeholders are **only read on the first boot**. Make later changes in the admin console, then copy them back into the JSON. Changing `GTN_WEB_URL` and similar variables on Render afterwards does nothing.
- **Logs:** **keycloak → Logs**. Login events are stored in the realm for 30 days (**gotravelnha → Events**).
- **Backups:** paid Render Postgres has point-in-time recovery (**keycloak-db → Recovery**). For an off-Render copy, run `pg_dump` with the external URL from a machine whose IP you have temporarily added to `ipAllowList`.
- **Scaling:** move the web service plan up first. Running more than one instance needs `KC_CACHE=ispn` and JGroups discovery, which Render doesn't provide out of the box, so stay on one bigger instance.
- **Upgrading Keycloak:** bump the tag in `Dockerfile` (both `FROM` lines) and the compose files. Read the upgrade notes and take a manual backup before deploying. Keycloak migrates its schema on boot.
